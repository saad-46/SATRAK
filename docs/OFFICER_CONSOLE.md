# Officer console (apps/web)

Status: implemented locally on branch `claude/satrak-compliance-workflow`; not pushed, no PR. Verified by the commands in "Verification". **Not production-ready**: R1–R8 in `docs/audit/SATRAK_IMPLEMENTATION_STATUS.md` remain open and this document lists the console's own gaps.

The console is a thin client of the existing API (PRD §13 / AP4): it holds no business rules. Every allowed action it offers comes from the server's `actions` blocks; every submission is validated again by the server, and the release gate (ADR-0014, Amendment 1) is enforced in the API and the database regardless of what the UI shows.

Terminology follows ADR-0014 Amendment 1: AI output is a **candidate** (never a "finding" or "violation"); an officer **verifies** it; only a **verified candidate** may open an **inspection case**; a **case finding** is the field inspector's site-visit record.

Navigation items are shown only when `/me` says the caller holds a matching permission. That is a usability aid; each API call enforces authorisation on its own.

## Authentication in the console

- The API validates OIDC bearer tokens (ADR-0013). **No identity-provider client exists in this repository**, so the console cannot start a real SSO flow and does not pretend to.
- `lib/auth/token-source.ts` supplies the token. The only implemented source is a **development-only manual token**, kept in `sessionStorage` (never `localStorage`, never in URLs or logs) and refused when `NEXT_PUBLIC_APP_ENV=production`. In production the sign-in screen states that SSO is not configured. Wiring the real OIDC flow means replacing this one module.
- A 401 from any call clears the token and returns to sign-in with an expiry message. A user with no grants (or a 403 from `/me`) sees "No access", never an empty console.
- Access-token lifetime is capped by the API (`max_token_lifetime_seconds`, default 900). IdP-driven revocation within 1 minute (NFR-18.2) is unproven (open item).

## Behaviour that is deliberately NOT done

- No "confirmed violation" wording anywhere: `labels.ts` maps statuses to "Unverified", "Evidence requested", "Verified by officer", "Rejected by officer". The model score is shown as "Model score (not a probability of violation)".
- A missing or unmatched permit is described as a data gap or matching condition, never as unauthorised construction.
- No before/after imagery, heatmap, KPI trend or chart is drawn: none exists in the data. The geometry viewer is an SVG schematic of stored GeoJSON and says so.
- "Overdue" is not shown as a number: SLA clocks (FR-10.4) do not exist, so the dashboard states that.
- No free-text search: the API has no searchable index; no search box is rendered.
- No assignee picker: there is no user directory API, so assignment takes a user UUID.
- No four-eyes rule: unchanged policy decision still open.

## Accessibility and UI notes

Skip link, `main` landmark, labelled `nav`s, breadcrumbs (`aria-current`), table captions and `scope` headers, form labels, `role=dialog` modals with `aria-modal`, labelled/described, focus trap, Esc, focus return; polite live regions for results; `role=alert` for failures; status never conveyed by colour alone; `prefers-reduced-motion` disables animation; visible `:focus-visible` ring; tables scroll horizontally on narrow screens; mobile navigation toggle with `aria-expanded`. Visual direction: deep navy/indigo tokens in `globals.css` (dark default, light available), no decorative transparency on text.

`axe-core` is **not installed** in the repository, and adding a dependency was not authorised, so the automated check is the in-repo structural audit `src/test/a11y-audit.ts` (accessible names, labels, `alt`, table headers, duplicate/missing ids, heading order, single `h1`). It cannot measure colour contrast or real focus order; a manual contrast and screen-reader pass is still required. Recommended follow-up (needs approval): add `axe-core` to the Playwright run.

### Running the real-API end-to-end check

`apps/api/tests/e2e_stack/serve.py` is a **test-only** harness: it rebuilds the schema of `SATRAK_TEST_DATABASE_URL` (the name must end in `_test`), seeds synthetic rows (`is_simulated`), mints short-lived tokens from the in-process fake issuer used by the API tests, and serves the real app on `127.0.0.1:8000`.

```
cd apps/api && python -m tests.e2e_stack.serve /tmp/e2e.json      # needs the CI-style PostGIS + roles
cd apps/web && pnpm build && E2E_STACK_FILE=/tmp/e2e.json pnpm test:e2e e2e/fullstack.spec.ts
```

It proves the console against the real server, RLS, release gate and audit log. It does **not** prove a production IdP, browser support beyond Chromium, or deployment. CI does not run Playwright today (and this change does not add that job).

## Open items and blockers specific to the console

1. Production OIDC sign-in (blocked: no IdP configuration or client registration in the repo; approver and IdP not named).
2. User directory (assignee picker, name display): none exists; ids are shown shortened.
3. Imagery rendering and before/after comparison: needs the imagery/tile service and an authorised provenance chain; references only today.
4. SLA clocks, free-text search, automatic assignment, exports: absent upstream.
5. Evidence upload for case findings: needs the evidence store.
6. `axe-core` and a manual contrast/screen-reader audit; Playwright is not in CI.
7. Cross-browser and device testing; performance budgets (NFR-8.1) unmeasured.
8. CodeQL's 82 alerts on PR #14 remain untriaged (details not retrievable from this session).
9. Manual accessibility review of the code (WCAG 2.1 AA checklist) found no blocking defect but left these unverified or open: colour contrast was not measured with a tool (tokens were chosen for high contrast, not audited); the modal traps focus but does not mark the page behind it inert, so a screen-reader virtual cursor can leave it; many controls are 32–36 px high (below the 44 px AAA target size; AA 2.1 has no minimum); no screen-reader pass was done.
